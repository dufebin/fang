# 上传时生成缩略图 — 设计文档

**日期：** 2026-11-16
**状态：** 已批准
**背景：** 小程序列表卡片(首页四宫格及各列表页单图封面)加载的是原图。后端上传压缩只降质量、不降分辨率,单张上限约 200KB,首页一屏 10 张卡约 8MB 流量。

## 目标

房源列表卡片改用缩略图(~30-60KB/张),详情页继续用原图。

## 方案选择

用户在两个方案中选定 **方案 B(上传时预生成缩略图)**,放弃按需缩放 + 缓存(方案 A)。代价是存量图片需要跑一次迁移脚本,已在范围内接受。

使用范围:小程序**所有列表卡片**(首页四宫格 + 各列表页单图封面),不只是首页。

## 设计

### 1. 后端 — LocalStorage.Save 生成缩略图

- 保存原图后,若图片**宽度 > 500px**,在同目录生成缩略图:
  - 命名:`<stem>_thumb.jpg`(如 `123.jpg → 123_thumb.jpg`;源是 png/gif 也统一输出 jpg)
  - 规格:宽 500px 等比缩小,JPEG quality 75
- 缩放算法:手写 box-filter 下采样平均(约 35 行),不引入新依赖。
- 跳过不生成的情况:
  - 宽 ≤ 500px(小图如头像自然跳过)
  - webp(Go 标准库无法解码)
- 缩略图生成失败只记日志,不影响原图保存和接口返回(纯优化,不 fail 主流程)。
- `Delete(key)` 顺带删除同名 `_thumb.jpg`。
- COS 存储模式不涉及(生产已迁移本地);若未来切回 COS,前端规则自动回退原图,无破坏。

### 2. 后端 — 存量迁移 `cmd/gen-thumbnails`

- 扫描 uploads 目录,为所有缺失 `_thumb.jpg` 的图片补生成。
- 幂等,可重复执行;支持 `-dry-run`(与现有 `cmd/migrate-cos-to-local` 风格一致)。
- 部署后在生产服务器执行一次。

### 3. 前端 — 小程序

- `utils/format.js` 新增 `thumbURL(url)`:
  - 空 → `''`
  - `http` 开头(遗留绝对 URL,无缩略图)→ 原图
  - 相对 `/uploads` 路径 → 替换为 `_thumb.jpg` 后缀
- `property-card` 组件:
  - `coverImage`(单图模式)和 `fourImgUrls`(四宫格)都改用 `thumbURL`
  - `<image>` 加 `binderror` 回退:缩略图加载失败(webp、迁移漏网)时换回原图,保证不出现空白图
- 详情页、H5、admin 不动,继续用原图。

### 4. API / DB

零改动。`PropertyImage.url` 字段不变,缩略图 URL 由前端按命名规则推导。

## 测试

- storage 包单测:
  - 生成缩略图的命名、宽度 ≤ 500、幂等
  - 小图(宽 ≤ 500px)跳过
  - webp 跳过
  - `Delete` 连带删除 `_thumb.jpg`
- `gen-thumbnails`:对小 fixture 目录跑一遍,验证幂等与 `-dry-run`。

## 部署清单

1. 后端发版(deploy-backend.sh)
2. 生产服务器执行一次 `gen-thumbnails`
3. 小程序发版(用户在微信开发者工具上传)

## 预期效果

列表图从 ≤200KB/张 降到 ~30-60KB/张,首页图片流量降至约 1/5~1/10。
