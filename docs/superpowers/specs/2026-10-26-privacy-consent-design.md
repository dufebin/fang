# 登录页隐私协议合规改造 设计文档

- 日期：2026-10-26
- 范围：微信小程序登录页隐私协议同意流程合规化，修复审核拒绝原因
- 涉及：仅 `frontend/miniprogram`

## 1. 背景与现状

小程序提审被拒，MP 后台「版本审核修改指引」页面列出 3 个失败原因：

1. **隐私政策不合规**：默认自动同意《用户服务协议》及《隐私政策》，应当由用户自主阅读后自行选择是否同意，不得默认强制用户同意。→ **代码问题，本次修复**
2. 类目不符（社交-陌生人/熟人交友）→ MP 后台补充类目，代码不动
3. 类目不符（社交-笔记）→ MP 后台补充类目，代码不动

现状问题（对应原因 1）：

- `frontend/miniprogram/pages/login/index.wxml:26`：只有文案「登录即表示同意《用户协议》和《隐私政策》」，无勾选框、无阅读环节，点登录即视为同意。
- 项目中不存在《用户服务协议》《隐私政策》正文页面，两个协议名甚至不可点击。
- 代码实际调用了多个隐私接口：`getUserInfo`/`chooseAvatar`（登录页）、`chooseMedia`（聊天发图 `pages/chat/index.js`）、`getLocation`（`pages/map-search/index.js`、`pages/property-edit/index.js`）。提审时选择「未采集用户隐私」与代码不符，存在隐私接口权限被回收的风险。

## 2. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 协议正文来源 | 小程序内置静态页面 | 用户选定；不依赖后端，改动最小 |
| 同意交互形式 | 登录页内嵌勾选框 + 未勾选拦截 | 标准合规做法；弹窗方案可选项弱 |
| 是否记住同意状态 | 不记住，每次进登录页默认不勾选 | 审核已拒过一次，从严处理；登录页出现频率低，无感（用户确认） |
| 官方隐私接口授权 | `app.json` 加 `"__usePrivacyCheck__": true` | 解决「选未采集隐私但代码调用隐私接口」的权限回收风险；微信官方弹窗机制 |

## 3. 前端设计

### 3.1 新增协议静态页（2 个）

- `pages/agreement/user` —《用户服务协议》
- `pages/agreement/privacy` —《隐私政策》

结构：标准 Page 四件套（js/wxml/wxss/json），`json` 设 `navigationBarTitleText` 为对应标题。正文用 `rich-text` 组件渲染内置 HTML 模板文本，js 内定义 `nodes` 数据。

文本内容为符合规范的通用模板（房产信息平台场景），隐私政策覆盖：

- 收集的信息范围：头像、昵称、位置信息、聊天图片、设备信息
- 用途说明（账号登录、房源定位、用户间沟通）
- 存储、保护与删除
- 用户权利（撤回同意、注销账号）
- 联系方式

两个页面注册进 `app.json` 的 `pages`（放 `pages/login/index` 之后）。

### 3.2 登录页改造（`pages/login`）

`index.wxml`：

- 删除第 26 行「登录即表示同意…」文案
- 登录按钮上方新增一行：`checkbox`（默认 `false`，不勾选）+「我已阅读并同意」+「《用户服务协议》」「《隐私政策》」两个可点击文本，`navigateTo` 至对应静态页

`index.js`：

- `data` 增加 `agreed: false`
- 新增 `onToggleAgreed`（checkbox change 事件）
- 新增 `onOpenUserAgreement` / `onOpenPrivacy` 两个跳转方法
- `onLogin` 开头校验：`!this.data.agreed` → `wx.showToast({ title: '请先阅读并同意用户服务协议和隐私政策', icon: 'none' })` 并 return，不发登录请求

登录逻辑、头像上传、跳转逻辑全部不动。

`index.wxss`：新增勾选行样式，匹配现有页面风格。

### 3.3 app.json

```json
"__usePrivacyCheck__": true
```

启用微信官方隐私 API 授权机制（隐私接口调用时由微信弹出官方隐私授权弹窗）。

## 4. 不改的部分

- 拒绝原因 2、3（社交类目）：MP 后台操作，代码不动
- 登录、上传、跳转逻辑不动

## 5. 后台待办（非代码，提醒用户）

1. MP 后台补充类目：社交-陌生人交友 或 社交-熟人交友（原因 2）
2. MP 后台补充类目：社交-笔记（原因 3）
3. MP 后台更新「用户隐私保护指引」，声明 chooseMedia/getLocation 等隐私接口（配合 `__usePrivacyCheck__`）

## 6. 验证方式

- 未勾选点登录 → toast 提示、无网络请求
- 点击《用户服务协议》/《隐私政策》→ 进入对应协议页，正文完整可读
- 勾选后点登录 → 流程与改造前完全一致（头像、昵称、跳转）
- 再次进入登录页 → 勾选框恢复未勾选状态
